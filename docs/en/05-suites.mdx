Each traffic suite is a directory under `/opt/traffic-generator/suites/` containing numbered shell scripts executed in order by `runner.sh`. Every script accepts the target FQDN as its first argument and writes output to both stdout and the results directory.

## csd-violations

**Scenarios:** 11 browser scenarios | **Runtime:** headed Chrome under Xvfb on AWS

`csd-violations` is the only maintained Client-Side Defense scenario source. Its versioned
manifest defines ordered navigation, evaluation, and explicit cleanup operations. The runner records each
operation's immediate outcome, browser-observed network state, screenshots, and cleanup status.

Every scenario ends with an explicit cleanup manifest step. That step removes run-scoped scripts,
links, images, overlays, listeners, timers, and synthetic controls where applicable, then asserts zero
remaining artifacts, zero populated controls, zero sensitive display values, zero tracked timers, and no
attached key listener. Network-request evidence objects are receipt data and require no DOM cleanup.

Every setup, action, assertion, and cleanup manifest step, plus each scenario's final state, must
produce a screenshot; a missing screenshot fails the scenario. The eleven scenarios therefore produce
45 step screenshots and 11 final screenshots (56 total) when the full suite runs. Final cleanup remains
a safety net before the final screenshot and browser-context destruction.

`receipt.json` contains the schema version, run ID, sanitized target protocol and host, run timestamps,
aggregate counts, scenario and step results, terminal network outcomes, instrumentation counts,
screenshot metadata, and browser/context cleanup. Screenshot metadata includes capture status, relative
path, intended object key, pending upload status, SHA-256, and masked-input count. The runtime does not
rewrite that receipt after upload. The separate `SHA256SUMS` file covers the local evidence files before
upload.

| Stable scenario | Route | Implemented browser activity and immediate evidence |
| --- | --- | --- |
| `login-credential-skimmer` | `/#/login` | Observes login fields, posts only the field count to `www.httpbin.org`, and asserts the terminal request state. |
| `registration-harvester` | `/#/register` | Observes registration controls, posts only the control count to `jsonplaceholder.typicode.com`, and asserts the terminal request state. |
| `payment-overlay-card-skimmer` | `/#/login` | Counts original controls, installs a masked display-only payment overlay, posts only the original-field count, then removes the overlay. |
| `obfuscated-loader` | `/` | Base64-decodes the fixed reviewed jsDelivr Lodash URL, injects it, and asserts `finished` or `blocked`. |
| `multi-cdn-injection` | `/` | Injects reviewed jsDelivr, esm.sh, unpkg, and ga.jspm.io scripts and records each terminal state. |
| `tag-manager-hijack` | `/` | Injects a reviewed jsDelivr Chart.js candidate with run-scoped tag-manager metadata, then removes the injected artifact. |
| `multi-channel-exfiltration` | `/#/login` | Observes login fields, then attempts counter-only fetch POST, image beacon, and link-prefetch channels to reviewed benign destinations. |
| `high-volume-domain-exfiltration` | `/#/login` | Attempts five reviewed script loads and two counter-only POSTs, retaining seven stable named sanitized outcomes and asserting each is terminal plus the aggregate counts. “High volume” means seven synthetic attempts, not volumetric load. |
| `form-overlay` | `/#/login` | Counts original controls, installs a value-free synthetic login overlay, asserts its geometry, then removes it. |
| `keylogger-simulation` | `/#/login` | Generates five synthetic keydown events, retains only the aggregate count, and asserts listener detachment and timer cleanup. |
| `maximum-detection` | `/#/login` | Composes the canonical field-observation, four-CDN, three-channel, banner, and cleanup primitives without duplicating implementations. |

The high-volume outcomes are `scriptJsdelivr`, `scriptEsm`, `scriptUnpkg`, `scriptJspm`,
`scriptChartjs`, `postHttpbin`, and `postJsonplaceholder`. Allowed terminal values are
`finished`, `blocked`, `failed`, and `timed-out`; `pending` fails the assertion.

The suite records whether the CSD sensor and `__imp_apg__/api/dip` requests appeared in the browser. That is browser evidence only; tenant observation remains a separate read-only correlation.

Headed Chrome under Xvfb, successful operations, screenshots, and uploaded evidence do **not** guarantee an F5 Distributed Cloud detection, timing, or risk classification; datacenter reputation, automation signals, population thresholds, aggregation, and filtering can affect observation.

<Aside type="caution">
  The external traffic-generator catalog does not automatically trigger
  Client-Side Defense detections. Run only against the authorized target, and
  present tenant telemetry only when it was actually observed.
</Aside>

## waf-encoding-evasion

**Scripts:** 7 | **Estimated Duration:** 5-10 minutes

Multi-layer encoding evasion attacks designed to test whether a WAF properly normalizes and
decodes payloads before inspection. Covers single, double, and triple URL encoding; HTML entity
encoding (decimal, hex, named, zero-padded); Unicode/UTF-8 insertion (zero-width space, BOM,
fullwidth characters, soft hyphen, overlong sequences); mixed/nested multi-layer encoding
(URL-encoded HTML entities, double-URL inside entities, 3-layer stacks); null byte injection; IIS
%uXXXX encoding; case manipulation; chunked transfer encoding body splitting; Base64 parameter
evasion; and header/cookie encoded payloads. Targets any application.

**F5 XC Feature:** WAF (encoding normalization depth)

| Order | Script                        | Tools           | Description                                                                                                                                                                                                                            |
| ----- | ----------------------------- | --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 01    | `01-url-encoding.sh`          | `curl`          | Single, double, and triple URL encoding of SQLi, XSS, and path traversal payloads across multiple endpoint paths. Tests whether the WAF decodes URL parameters recursively.                                                            |
| 02    | `02-html-entity-encoding.sh`  | `curl`, python3 | Decimal, hex, named, and zero-padded HTML entity encoding of attack payloads in both GET parameters and POST bodies. Includes template injection via `&#123;&#123;7*7&#125;&#125;`.                                                    |
| 03    | `03-unicode-utf8-evasion.sh`  | `curl`          | Zero-width space (U+200B), BOM (U+FEFF), fullwidth character, soft hyphen, and ZWNJ insertion into SQL keywords and XSS tags. Tests overlong UTF-8 sequences (2-byte and 3-byte).                                                      |
| 04    | `04-mixed-nested-encoding.sh` | `curl`          | Multi-layer payloads: URL-encoded HTML entities, double-URL inside entities, triple-layer stacks, JSON body with Unicode escapes (`<`), and the user's specific `{{7*7}}` template injection pattern.                                  |
| 05    | `05-null-byte-iis-base64.sh`  | `curl`          | Null byte injection (`%00`) for extension bypass, IIS `%uXXXX` Unicode encoding, and Base64-encoded payloads in URL parameters with decode flags.                                                                                      |
| 06    | `06-case-chunked-evasion.sh`  | `curl`          | Case randomization combined with encoding (`%3CsCrIpT%3E`), chunked transfer encoding to split SQL/XSS keywords across HTTP chunks, Content-Length/Transfer-Encoding conflict probes, and alternate path separators (`%5c`, `%c0%af`). |
| 07    | `07-header-cookie-evasion.sh` | `curl`          | Encoded attack payloads injected via Cookie, Referer, User-Agent, X-Forwarded-For, and X-Original-URL headers. Tests whether the WAF inspects and decodes all HTTP header fields, not just query parameters and POST bodies.           |

**Expected F5 XC Behavior:** A properly configured WAF should normalize all encoding layers
before pattern matching. Single-encoded payloads should be blocked immediately. Double and triple
encoding tests reveal the depth of the WAF's decode pipeline. Unicode insertion tests reveal
whether invisible characters are stripped before keyword matching. Results where encoded variants
pass while plain-text equivalents are blocked indicate normalization gaps in the WAF policy.
