## What This Provides

The Traffic Generator produces controlled attack traffic, reconnaissance scans, bot simulations, API abuse patterns, and browser-driven Client-Side Defense scenarios against an F5 Distributed Cloud HTTP load balancer. Choose either the existing Azure deployment or the independent AWS deployment. They share suite intent, but they do not imply cloud, runtime, or detection parity.

The Azure path provisions its established toolset with cloud-init. The AWS path uses a public-subnet
worker with an explicit Elastic IP, SSH restricted to the operator jumpbox's current public `/32`,
Systems Manager recovery, immutable source and runtime inputs, and sanitized browser evidence. A
completed browser scenario proves execution and evidence capture; it does not guarantee a corresponding
F5 Distributed Cloud detection.

For AWS Client-Side Defense, `csd-violations` is the only maintained suite. Other suite entries below describe the existing Azure deployment.

## Catalog and operations

The Azure catalog retains 164 scenarios across 22 suites, including eleven CSD browser scenarios and two
benchmarks. [Traffic suites](./05-suites/) lists every stable ID; [Runner](./06-runner/) documents discovery
and `tgen-control`; [Continuous catalog](./continuous-catalog/) explains the shared pacing and native
acceptance boundary. [Current tasks](./continuous-catalog-tasks/) and the [historical
archive](./archive/continuous-catalog-history/) keep source, installed, rendered and final qualification
separate. [DVWA mapping](./dvwa-payload-mapping/) retains all 15 SQLi and 18 XSS payloads.

All fourteen declared functional contracts still require exact-source installed evidence, and 150 scenarios lack functional contracts. Neither source inventory nor historical success establishes current complete catalog acceptance. CSD activity in WAAP is display-only with `csd_enabled=false`.
